2 Architecture Options (End-to-End)

Option A: Batch CDC with DLT Recommended

SQL Server (CDC enabled) ↓ JDBC (incremental query — every 5-15 min) Databricks Job (Scheduled Extract) ↓ Writes CDC changes to Landing Zone (Delta/Parquet) DLT Pipeline (Triggered mode) ↓ Auto Loader reads new files ↓ Bronze (raw CDC events) ↓ Silver (APPLY CHANGES INTO — SCD Type 1/2) ↓ Gold (aggregated views)

Option B: Streaming CDC with Kafka + DLT Near Real-Time

SQL Server (CDC enabled) ↓ Debezium CDC Connector Apache Kafka / Azure Event Hubs ↓ Kafka Source in DLT DLT Pipeline (Continuous mode) ↓ Bronze (raw CDC stream) ↓ Silver (APPLY CHANGES INTO) ↓ Gold (materialized views)

Option C: Direct JDBC CDC with DLT Simplest

SQL Server (CDC / CT / Watermark) ↓ DLT Pipeline with dlt.read_stream() or scheduled JDBC ↓ Bronze → Silver → Gold ↓ Watermark stored in Delta table

3 SQL Server Side Setup

3a. Enable CDC on SQL Server

SQL
-- Enable CDC on the database
USE HRDatabase;
EXEC sys.sp_cdc_enable_db;

-- Enable CDC on each table
EXEC sys.sp_cdc_enable_table
    @source_schema = N'dbo',
    @source_name   = N'DimEmployee',
    @role_name     = NULL,           -- NULL = no role restriction
    @supports_net_changes = 1;       -- enable net changes (deduplicated)

-- Verify CDC is enabled
SELECT name, is_cdc_enabled FROM sys.databases WHERE name = 'HRDatabase';
SELECT * FROM cdc.change_tables;

3b. CDC Query to Extract Changes

SQL
-- Get all changes since last LSN (Log Sequence Number)
DECLARE @from_lsn binary(10) = sys.fn_cdc_get_min_lsn('dbo_DimEmployee');
DECLARE @to_lsn   binary(10) = sys.fn_cdc_get_max_lsn();

SELECT
    __$operation,        -- 1=delete, 2=insert, 3=before-update, 4=after-update
    __$start_lsn,
    __$update_mask,
    *
FROM cdc.fn_cdc_get_all_changes_dbo_DimEmployee(
    @from_lsn, @to_lsn, N'all update old'
);

-- Or net changes (only final state per key — better for MERGE)
SELECT *
FROM cdc.fn_cdc_get_net_changes_dbo_DimEmployee(
    @from_lsn, @to_lsn, N'all'
);
💡 __$operation Values 1 = DELETE  |  2 = INSERT  |  3 = Before UPDATE (old values)  |  4 = After UPDATE (new values)

3c. Change Tracking (Alternative — Simpler)

SQL
-- Enable Change Tracking on database
ALTER DATABASE HRDatabase
SET CHANGE_TRACKING = ON (CHANGE_RETENTION = 7 DAYS, AUTO_CLEANUP = ON);

-- Enable on table
ALTER TABLE dbo.DimEmployee
ENABLE CHANGE_TRACKING WITH (TRACK_COLUMNS_UPDATED = ON);

-- Query changes since last sync version
DECLARE @last_version BIGINT = 0;  -- stored from previous run
SELECT ct.SYS_CHANGE_OPERATION, ct.SYS_CHANGE_VERSION, t.*
FROM dbo.DimEmployee t
RIGHT JOIN CHANGETABLE(CHANGES dbo.DimEmployee, @last_version) ct
    ON t.EmployeeID = ct.EmployeeID;

4 Databricks DLT Pipeline for CDC

4a. Bronze Layer — Ingest Raw CDC Events

Python — DLT
# DLT notebook: 01_CDC_Bronze.py
import dlt
from pyspark.sql.functions import *

# Option 1: Auto Loader from Landing Zone (files written by Extract job)
@dlt.table(
    name="bronze_employee_cdc",
    comment="Raw CDC events from SQL Server",
    table_properties={
        "quality": "bronze",
        "pipelines.autoOptimize.managed": "true",
    }
)
def bronze_employee_cdc():
    return (
        spark.readStream
            .format("cloudFiles")
            .option("cloudFiles.format", "parquet")
            .option("cloudFiles.inferColumnTypes", "true")
            .option("cloudFiles.schemaLocation",
                    "/mnt/checkpoints/employee_cdc_schema")
            .load("/Volumes/dev_volumes/hr/landing/cdc/DimEmployee/")
            .withColumn("_ingest_ts", current_timestamp())
            .withColumn("_source_file", input_file_name())
    )

# Option 2: Kafka / Event Hubs source (for Debezium CDC)
@dlt.table(name="bronze_employee_kafka")
def bronze_employee_kafka():
    return (
        spark.readStream
            .format("kafka")
            .option("kafka.bootstrap.servers",
                    "your-eventhub.servicebus.windows.net:9093")
            .option("subscribe", "sqlserver.dbo.DimEmployee")
            .option("kafka.security.protocol", "SASL_SSL")
            .option("kafka.sasl.mechanism", "PLAIN")
            .option("kafka.sasl.jaas.config",
                'org.apache.kafka.common.security.plain.'
                'PlainLoginModule required '
                'username="$ConnectionString" '
                'password="Endpoint=sb://...";')
            .option("startingOffsets", "earliest")
            .option("maxOffsetsPerTrigger", "100000")
            .load()
            .select(
                col("key").cast("string").alias("_key"),
                from_json(col("value").cast("string"),
                          cdc_schema).alias("data"),
                col("timestamp").alias("_kafka_ts"),
                col("offset").alias("_kafka_offset"),
            )
            .select("_key", "_kafka_ts", "_kafka_offset", "data.*")
    )

4b. Silver Layer — APPLY CHANGES INTO (SCD Type 1 / Type 2)

🔄 SCD Type 1 — Overwrite with Latest

Keeps only the current version of each row. Previous values are lost.

📚 SCD Type 2 — Full History

Keeps all historical versions with __START_AT, __END_AT, __IS_CURRENT columns.

Python — DLT Silver
# DLT notebook: 02_CDC_Silver.py
import dlt
from pyspark.sql.functions import *

# ── SCD Type 1 (overwrite with latest) ──
dlt.create_streaming_table(
    name="silver_employee",
    comment="Cleansed employee dimension — SCD Type 1",
    table_properties={"quality": "silver"},
)

dlt.apply_changes(
    target="silver_employee",
    source="bronze_employee_cdc",
    keys=["EmployeeID"],                      # primary key(s)
    sequence_by=col("__$start_lsn"),          # CDC ordering column
    apply_as_deletes=expr("__$operation = 1"),# operation 1 = DELETE
    except_column_list=[                      # exclude CDC metadata
        "__$operation", "__$start_lsn",
        "__$update_mask", "_ingest_ts", "_source_file"
    ],
    stored_as_scd_type=1,                     # Type 1: overwrite
)

# ── SCD Type 2 (keep full history) ──
dlt.create_streaming_table(
    name="silver_employee_history",
    comment="Employee dimension — SCD Type 2 (full history)",
    table_properties={"quality": "silver"},
)

dlt.apply_changes(
    target="silver_employee_history",
    source="bronze_employee_cdc",
    keys=["EmployeeID"],
    sequence_by=col("__$start_lsn"),
    apply_as_deletes=expr("__$operation = 1"),
    except_column_list=[
        "__$operation", "__$start_lsn",
        "__$update_mask", "_ingest_ts", "_source_file"
    ],
    stored_as_scd_type=2,  # adds __START_AT, __END_AT, __IS_CURRENT
)

4c. Data Quality Expectations in DLT

@dlt.table(name="silver_employee_validated")
@dlt.expect_or_drop("valid_employee_id", "EmployeeID IS NOT NULL")
@dlt.expect_or_warn("valid_name", "LENGTH(FirstName) > 0")
@dlt.expect_or_fail("valid_hire_date", "HireDate <= current_date()")
def silver_employee_validated():
    return dlt.read_stream("bronze_employee_cdc").select(
        "EmployeeID", "FirstName", "LastName", "Email",
        "DepartmentID", "HireDate", "Salary",
        current_timestamp().alias("_processed_ts"),
    )
DLT Expectation Actions @dlt.expect — log warning, keep row  |  @dlt.expect_or_warn — log metric, keep row  |  @dlt.expect_or_drop — drop failing rows  |  @dlt.expect_or_fail — fail pipeline on violation

5 CDC Extract Job (JDBC — Scheduled Every 5-15 min)

Python — Databricks Notebook
# Databricks notebook: CDC_Extract.py
# Runs on a schedule (Databricks Job or Workflow)

import json
from pyspark.sql import functions as F
from datetime import datetime

# Read last LSN/watermark from Delta table
watermark_table = "`admin_source`.`Configtables`.wf_watermark_metadata"
table_name = "dbo.DimEmployee"

try:
    wm = spark.sql(f"""
        SELECT last_value FROM {watermark_table}
        WHERE table_name = '{table_name}'
    """).collect()[0]["last_value"]
except:
    wm = None  # First run — full extract

# JDBC connection
jdbc_url = ("jdbc:sqlserver://your-server:1433;"
            "databaseName=HRDatabase;encrypt=true")
jdbc_props = {
    "user": dbutils.secrets.get("sql-scope", "username"),
    "password": dbutils.secrets.get("sql-scope", "password"),
    "driver": "com.microsoft.sqlserver.jdbc.SQLServerDriver",
}

# Build CDC query
if wm:
    # Incremental: get changes since last LSN
    query = f"""(
        SELECT __$operation, __$start_lsn, __$update_mask, *
        FROM cdc.fn_cdc_get_all_changes_dbo_DimEmployee(
            0x{wm}, sys.fn_cdc_get_max_lsn(), N'all update old'
        )
    ) AS cdc_data"""
else:
    # Initial full load
    query = "dbo.DimEmployee"

df = spark.read.jdbc(jdbc_url, query, properties=jdbc_props)
df = df.withColumn("_extract_ts", F.current_timestamp())

# Write to landing zone as Parquet (Auto Loader will pick up)
batch_id = datetime.now().strftime("%Y%m%d_%H%M%S")
output_path = (f"/Volumes/dev_volumes/hr/landing/"
               f"cdc/DimEmployee/{batch_id}")
df.write.mode("overwrite").parquet(output_path)

# Update watermark
new_lsn = (df.agg(F.max("__$start_lsn").cast("string"))
             .collect()[0][0])
if new_lsn:
    spark.sql(f"""
        MERGE INTO {watermark_table} AS t
        USING (SELECT '{table_name}' AS table_name,
                      '{new_lsn}' AS last_value) AS s
        ON t.table_name = s.table_name
        WHEN MATCHED THEN UPDATE SET
            t.last_value = s.last_value,
            t.updated_at = current_timestamp()
        WHEN NOT MATCHED THEN INSERT
            (table_name, last_value, watermark_column, updated_at)
            VALUES (s.table_name, s.last_value,
                    '__$start_lsn', current_timestamp())
    """)

8 Best Practices

📊 Data Pipeline
  • Use APPLY CHANGES INTO — DLT's built-in CDC handler for automatic MERGE/SCD logic
  • Sequence by LSN or timestamp — ensures correct ordering of changes
  • Use Auto Loader (cloudFiles) — exactly-once, schema evolution, efficient file discovery
  • Separate CDC from full loads — different pipelines for initial bulk vs incremental CDC
  • Store CDC operation type — keep __$operation in Bronze for audit, strip in Silver
  • Handle late-arriving data — use sequence_by to resolve out-of-order events
⚡ Performance
  • Batch CDC every 5-15 min — balance between freshness and cost
  • Use Photon — accelerates DLT processing 2-5x
  • Partition landing by date — landing/cdc/Table/2026/03/19/ for efficient Auto Loader
  • Set maxOffsetsPerTrigger for Kafka — prevents large spike processing
  • Use Z-ORDER on frequently queried columns in Silver/Gold tables
  • Enable auto-compaction — pipelines.autoOptimize.managed = true
🛡️ Reliability
  • Idempotent writes — Auto Loader tracks processed files; DLT handles checkpointing
  • Dead-letter handling — use @dlt.expect_or_quarantine for bad records
  • Monitor CDC lag — alert if sys.fn_cdc_get_max_lsn() gap grows
  • CDC cleanup retention — set @retention period > your max pipeline delay
  • Watermark persistence — store in Delta table, not in-memory
  • Schema evolution — cloudFiles.schemaEvolutionMode = "addNewColumns"
🔒 Security
  • Never hardcode passwords — use Databricks Secrets (dbutils.secrets.get())
  • Encrypt JDBC — always encrypt=true;trustServerCertificate=false for Azure SQL
  • UC RBAC — grant minimal permissions per catalog/schema
  • Private networking — use Private Link for Azure SQL ↔ Databricks
💰 Cost Optimization
  • Triggered mode for batch CDC (cluster only runs when scheduled)
  • Continuous mode only when sub-minute latency is required
  • Serverless DLT — auto-scales to zero when idle (if available)
  • Spot instances for non-critical CDC processing
  • Delta sharing — share Silver/Gold tables without copying data

CDC Lag Monitoring (Run on SQL Server)

SQL — SQL Server
-- CDC lag monitoring
SELECT
    capture_instance,
    DATEDIFF(MINUTE,
        sys.fn_cdc_map_lsn_to_time(
            sys.fn_cdc_get_min_lsn(capture_instance)
        ),
        GETDATE()
    ) AS lag_minutes
FROM cdc.change_tables;
⚠️ Key Alerts to Set Up
  • CDC lag exceeds 30 minutes → investigate SQL Server Agent job
  • DLT pipeline failure → check event log for error details
  • Row count anomaly (>50% change) → potential data quality issue
  • Watermark not advancing → extract job may be failing silently

11 Recommendation for Your Project

✅ Recommended Approach: SQL Server CDC + DLT (Batch Triggered) Given your current architecture (SQL Server HR database → Databricks Unity Catalog with MetadataFlow + AutoInfraCreation), here is the recommended implementation path:
  1. Enable SQL Server CDC on your HR tables (DimEmployee, DimDepartment, DimJobRole, DimLocation, DimDate) using sys.sp_cdc_enable_table
  2. Add a CDC Extract notebook (scheduled every 5-15 min) that reads cdc.fn_cdc_get_net_changes_* via JDBC and writes Parquet to UC Volumes landing zone
  3. Create a DLT pipeline with Auto Loader (Bronze) + APPLY CHANGES INTO (Silver) for automatic SCD handling
  4. Use triggered mode (not continuous) to keep costs low — 5-15 min latency is sufficient for HR dimension tables
  5. Store LSN watermarks in your existing wf_watermark_metadata Delta table

This integrates cleanly with your existing MetadataFlow + AutoInfraCreation infrastructure. The watermark table, pipeline groups, and job metadata all remain compatible — only the extract query changes from full-table JDBC to CDC function calls.

❌ Current (Watermark-based)

  • Requires reliable timestamp column
  • Full table scan if no watermark
  • Manual MERGE logic in notebooks

✅ With CDC + DLT

  • Captures INSERT, UPDATE, DELETE
  • Uses LSN — works on any table
  • Only reads changed rows from log
  • APPLY CHANGES INTO handles SCD automatically
